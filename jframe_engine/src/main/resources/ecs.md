# JFrame ECS · 游戏对象行为引擎 — 功能介绍

> 面向管理者的功能概览。技术人员请看包内《README.md（使用手册）》与《DEVELOPER.md（维护手册）》。

---

## 一句话介绍

让服务器里的箱子、怪物、任意游戏对象都能**自动获得智能行为**——程序员把行为做成标准积木，策划用一份配置文件就能拼出新玩法。**服务器里已经摆好的、和玩家以后新放的，全部自动识别。**

## 核心数字

- **1 条规则 = 全服生效**（存量 + 后放全覆盖）
- **5 类标准积木**（组件 / 选择器 / 生成器 / 解析器 / 系统）
- **4 级事件精准过滤**（只打扰该被打扰的对象）
- **56 项自动化测试全绿**，16 个模块构建通过

## 一、核心能力

| # | 能力 | 说明 |
|---|------|------|
| 1 | **存量 + 后放，全自动识别** | 服里已摆的 300 个箱子，一条规则全部生效；玩家之后新放的下一秒自动跟上；砸掉、区块加载等边界全自动处理，不需逐个设置、不存在漏网 |
| 2 | **配置即玩法，运营自己调** | 掉落率、作用范围、触发阈值全写在配置文件里；活动加码、数值平衡不用改代码、不用发版，改一份 YAML 即可 |
| 3 | **积木复用，新玩法 = 重新组合** | "告警""掉落表""波次"写一次，可挂到箱子、怪物、任何对象；新活动不再是新开发，上线周期从周降到天 |
| 4 | **性能可控，故障自动隔离** | 只处理"挂了行为的对象"（索引直查不全服扫描）；单个行为写错只记一条日志不会崩服；行为下线自动清理不留脏数据 |

## 二、三个具体场景

### 场景 A：周末魔法箱活动

**需求**：全服箱子变魔法箱（音效 + 加倍掉落），出生点 64 格内的"守卫箱"更稀有。

**成本**：1 个行为组件（约 30 行代码）+ 策划一份配置：

```yaml
all-chests:          # 所有箱子
  selector: { use: blockentity-class, params: { type: BlockEntityChest } }
  components: [ { id: magic-alarm, params: { radius: 8.0 } } ]

guardian-chests:     # 出生点附近加码
  selector: { use: near-spawn, params: { distance: 64 } }
  components: [ { id: magic-alarm, params: { radius: 12.0 } } ]
```

**效果**：

- 启动瞬间，300 个存量箱全部生效；
- 玩家新放的箱子 1 秒内自动跟上；
- 砸掉自动清理；活动结束一键还原，不留脏数据。

### 场景 B：夜间幽灵波次

**需求**：每晚 9 点广场刷 5 只幽灵，全灭进下一波，波次越高越难。

**成本**："波次状态"组件 + 一个"生成一群怪物"的生成器配置；波次管理器是纯虚拟对象，不占世界实体、不占刷新配额。

**效果**：定时一次 `spawn("night-ghosts", 广场坐标)` → 5 只幽灵自动挂上行为；全灭自动卸载、波次 +1；次日晚从上一波无缝续刷。

### 场景 C：高价值箱子审计

**需求**：特定奖励箱被谁打开要记账；被高频打击（伤害 > 4）要实时告警。

**成本**：审计组件声明"监听打开事件 + 伤害超阈值才处理"，引擎把事件精准投递到那一个箱子的行为上。

**效果**：只有挂了审计组件的箱子收到事件，普通箱子零开销；处理出错只记日志，服务不中断。

## 三、同一件事，两种做法

| 常见需求 | 传统做法 | 用本引擎 |
|---------|---------|---------|
| 给某类对象统一加行为 | 每种对象写一套监听器，手动维护状态表，还要兜放置/破坏/区块加载边界 | **一条配置规则**，存量与新增全覆盖，边界全自动 |
| 活动数值调整 | 改代码 → 编译 → 发版 → 重启，运营排程序员档期 | **改配置文件**即可，运营自己掌握节奏 |
| 上线一个新玩法 | 从零开发一套逻辑，按周计 | 已有积木**重新组合**，按天计 |
| 行为下线 / 活动结束 | 手动清状态、注销监听，漏一步留脏数据 | **自动清理**，干净还原 |
| 某个行为写错 | 常见连带整服报错甚至崩溃 | **自动隔离**，只记一条日志，其余照常 |
